This module sends OpenTelemetry data from Odoo to an external collector.

OpenTelemetry (OTel) is an open standard for traces, logs and metrics.

Module's core features:

- Sends the data with the OpenTelemetry Protocol (OTLP) over HTTP
  (OTLP/HTTP).
- Operates in "fail-open" mode. An OpenTelemetry error does not change
  the result or the exception of a business operation.
- Hides sensetive data in logs and traces.
- The module does not create database tables for telemetry data.

The module exports these signals:

- Traces of incoming HTTP requests.
- Selected records of the standard Python ``logging`` module.
- Structured events of integrations.
- Spans for specified methods. You can create these spans manually or
  with a decorator.

Use Cases / Context
===================

Odoo has no built-in tools to analyze logs or traces. It only writes
plain text lines to a log file (set by the ``logfile`` option in
``odoo.conf``) or, if this option is empty, to stdout. This output has
several limits:

- The lines are unstructured text, so they are hard to search and
  filter.
- The lines are not linked to a request or an operation, so you cannot
  see everything that happened during one call.
- Old files are usually rotated and deleted by an external tool, so the
  history is short.

Because of this, integration modules often store their own technical
logs in Odoo models: raw HTTP requests and responses, webhook calls, and
so on. These records are not business data, but they grow the PostgreSQL
database and make it slower.

This module solves both problems. It sends traces and structured logs to
an external observability system using OpenTelemetry. Each log record is
linked to the request or operation that produced it, and the Odoo
database keeps only business data.

Installation
============

Python dependencies
-------------------

Install these Python packages in the Odoo environment:

- ``opentelemetry-api``
- ``opentelemetry-sdk``
- ``opentelemetry-exporter-otlp-proto-http``
- ``opentelemetry-instrumentation-logging``

**Note:** ``requirements.txt`` file contains these packages:

.. code:: bash

   pip install -r requirements.txt

Module installation
-------------------

1. Add the repository directory to ``addons_path``.
2. Restart Odoo.
3. Install the ``xxp_otel`` module.

Observability backend
---------------------

The module does not depend on a specific vendor. The module needs a
receiver that accepts OTLP/HTTP. You can use the OpenTelemetry Collector
or an observability backend with OTLP/HTTP ingestion.

Install the receiver on a server that is not the Odoo or PostgreSQL
server.

**Warning:** Do not open the OTLP ingestion port to the internet. Open
it only to the Odoo servers.

Before you use the receiver in production, do a check of these items:

- Network and firewall rules.
- Authentication of the OTLP ingestion.
- Data retention.
- CPU, RAM and disk sizing.

Configuration
=============

By default, the module is disabled.

The module reads its parameters from the ``[options]`` section of the
Odoo configuration file (``odoo.conf`` or the ``--config`` option).
After you change a parameter, restart Odoo.

The module does not use the ``OTEL_*`` and ``XXP_OTEL_*`` environment
variables. When the SDK starts, the module removes these variables for a
short time. Thus, the exporter does not read them.

Minimum configuration
---------------------

.. code:: ini

   [options]
   otel_enabled = true
   otel_service_name = odoo
   otel_otlp_endpoint = http://otel-collector:4318
   otel_otlp_headers = Authorization=Basic <base64>
   otel_otlp_timeout = 5

``otel_otlp_endpoint`` is the base URL for OTLP ingestion. Do not add a
slash at the end. The module adds ``/v1/traces`` and ``/v1/logs`` to the
base URL. Some backends use a path prefix, for example
``http://<host>:<port>/<prefix>``. Refer to the documentation of your
backend.

``otel_otlp_headers`` contains the authentication headers that your
backend requires.

For production, set ``otel_otlp_timeout = 5``. This value is the maximum
time that one send operation holds the export thread. This value is also
a part of the worker stop time.

The default values are applicable to production:

- The module samples 10% of traces (``parentbased_traceidratio``,
  ``0.1``).
- The module exports log records that it selects by prefix only from the
  ``WARNING`` level.
- The module does not write request parameters to spans.
- The module does not trace the ``/websocket`` and ``/longpolling``
  routes.

Full configuration example
--------------------------

.. code:: ini

   [options]
   otel_trace_http = true
   otel_trace_rpc = true
   otel_trace_routes = /web/dataset,/web/login
   otel_trace_exclude_routes = /websocket,/longpolling,/web/static,/web/assets
   otel_traces_sampler = parentbased_traceidratio
   otel_traces_sampler_arg = 0.1
   otel_capture_request_params = false
   otel_log_level = INFO
   otel_log_prefixes = odoo.addons.my_integration,odoo.addons.my_webhook
   otel_log_prefix_level = WARNING
   otel_max_message_length = 32768
   otel_max_attribute_length = 32768
   otel_max_collection_items = 100
   otel_max_depth = 6
   otel_max_event_bytes = 262144
   otel_log_queue_max_bytes = 33554432
   otel_log_max_queue_size = 2048
   otel_log_max_export_batch_size = 64
   otel_log_schedule_delay = 200
   otel_redact_keys = private_key,signature
   otel_otlp_traces_endpoint = http://otel-collector:4318/v1/traces
   otel_otlp_logs_endpoint = http://otel-collector:4318/v1/logs
   otel_otlp_headers = Authorization=Basic <base64>
   otel_otlp_timeout = 5

~~~~~~

+---------------------------------+------------------------------+----------------------+
| Parameter                       | Default                      | Description          |
+=================================+==============================+======================+
| ``otel_trace_http``             | ``true``                     | Creates a server     |
|                                 |                              | span for each        |
|                                 |                              | incoming HTTP        |
|                                 |                              | request.             |
+---------------------------------+------------------------------+----------------------+
| ``otel_trace_rpc``              | ``true``                     | Adds ``odoo.model``  |
|                                 |                              | and ``odoo.method``  |

+---------------------------------+------------------------------+----------------------+
| ``otel_trace_routes``           | empty                        | Route prefixes to    |
|                                 |                              | trace. If empty, the |
|                                 |                              | module traces all.   |
+---------------------------------+------------------------------+----------------------+
| ``otel_trace_exclude_routes``   | ``/websocket,/longpolling``  | Route prefixes that  |
|                                 |                              | the module does not  |
|                                 |                              | trace.               |
+---------------------------------+------------------------------+----------------------+
| ``otel_traces_sampler``         | ``parentbased_traceidratio`` | The trace sampler.   |
+---------------------------------+------------------------------+----------------------+
| ``otel_traces_sampler_arg``     | ``0.1``                      | The sample ratio,    |
|                                 |                              | from ``0.0`` to      |
|                                 |                              | ``1.0``.             |
+---------------------------------+------------------------------+----------------------+
| ``otel_capture_request_params`` | ``false``                    | Writes request       |
|                                 |                              | parameters to spans. |
+---------------------------------+------------------------------+----------------------+

``otel_traces_sampler`` accepts these values:

- ``always_on``
- ``always_off``
- ``traceidratio``
- ``parentbased_always_on``
- ``parentbased_always_off``
- ``parentbased_traceidratio``

If the value is unknown, the module uses ``parentbased_always_on``. The
``parentbased_*`` samplers use the decision of the caller system if the
caller sends a ``traceparent`` header.

``otel_trace_routes`` limits HTTP traces to a list of route prefixes. If
the value is empty, the module traces all requests.

``otel_trace_exclude_routes`` removes routes from tracing. This list has
priority over ``otel_trace_routes``.

**Note:** Your value of ``otel_trace_exclude_routes`` replaces the
default value. Thus, add ``/websocket`` and ``/longpolling`` to your
list.

The module compares a prefix with a route at the ``/`` boundary. For
example, ``/web`` matches ``/web/login``, but ``/web`` does not match
``/webhook``. The module compares the prefix with the Werkzeug route
pattern and with the real path.

Request parameters
~~~~~~~~~~~~~~~~~~

By default, ``otel_capture_request_params`` is ``false``. If you set it
to ``true``, the module writes the parsed request parameters to the
``odoo.request.params`` span attribute. The parameters include:

- The query string.
- The route arguments.
- The JSON-RPC ``params``, with ``args`` and ``kwargs``.

The module does not read the raw HTTP body.

The attribute is one valid JSON string. Its maximum size is
``otel_max_attribute_length`` bytes in UTF-8. The module redacts secret
keys in the attribute with the same rules as for logs. The module writes
the attribute only for recorded spans. Thus, the module does not collect
parameters for requests that the sampler does not select.

Size and memory limits
----------------------

The module sanitizes each exported event one time, in the OpenTelemetry
handler. The module does this only if it will send the record. Thus, the
record level must pass the filter, and the export must not be in pause.

================================== ==================== ===========
Parameter                          Default              Minimum
================================== ==================== ===========
``otel_max_event_bytes``           ``262144`` (256 KB)  ``1024``
``otel_max_depth``                 ``6``                ``1``
``otel_max_attribute_length``      ``32768``            ``256``
``otel_max_collection_items``      ``100``              ``1``
``otel_max_message_length``        ``32768``            ``256``
``otel_log_queue_max_bytes``       ``33554432`` (32 MB) ``1048576``
``otel_log_max_queue_size``        ``2048``             ``1``
``otel_log_max_export_batch_size`` ``64``               ``1``
``otel_log_schedule_delay``        ``200`` (ms)         ``50``
================================== ==================== ===========

- ``otel_max_event_bytes`` is the total size of one event in UTF-8
  bytes. The size includes JSON escape characters. The module fills the
  budget in this sequence: the message text, the exception, the
  structured metadata and ``odoo.capture``. A Cyrillic character uses 2
  bytes. An emoji uses 4 bytes.
- ``otel_max_depth`` is the maximum nesting depth. At a deeper level,
  the module writes ``"<max-depth>"``.
- ``otel_max_attribute_length`` and ``otel_max_collection_items`` are
  the limits for usual structured metadata. The event budget is the only
  limit for the arguments and the result that ``observe_method``
  captures. Thus, the module keeps an API response of 100 KB fully.
- ``otel_max_message_length`` is the limit for the message text and for
  the exception stack trace.
- ``otel_log_queue_max_bytes`` is the maximum size of log data in the
  queue and in the current send operation, for one process. If the
  collector is slow or does not respond, the module discards new
  records. It does not remove old records. The module writes a warning
  about the number of discarded records a maximum of one time each
  minute.
- ``otel_log_max_queue_size`` and ``otel_log_max_export_batch_size`` are
  the limits of the queue and of the batch, in records. The module also
  divides a batch into OTLP requests of a maximum of 4 MB.
- ``otel_log_schedule_delay`` is the interval between two send
  operations if the queue has fewer records than
  ``otel_log_max_export_batch_size``. A short interval keeps fewer large
  events in memory. With a continuous flow of logs, one process sends a
  maximum of 5 requests each second.

Memory estimate
~~~~~~~~~~~~~~~

If the collector is not available, one worker can use this quantity of
memory for telemetry:

- ``otel_log_queue_max_bytes``.
- Plus one serialized request (a maximum of 4 MB).
- Plus the spans in the queue (a maximum of 2048 spans).

With the default values, 12 workers can use approximately 450 MB in the
worst case. If the collector operates correctly, the queue is almost
empty.

Usage
=====

For developers
--------------

The module already exports the standard Odoo logs and traces.

You can extend the traced data. To do this, customize a technical
module.

The sections below show the procedures.

1. Log an event
---------------

.. code:: python

   import logging

   _logger = logging.getLogger(__name__)  # the standard Odoo logger

   _logger.info(
       "External API request completed",  # short text, no payload here
       extra={
           "otel_event": "integration.response",  # always export this record
           "integration.name": "external_api",
           "request_payload": request_payload,  # dict or JSON string
           "response_payload": response.json(),  # secrets become "***"
       },
   )

2. Add a span
-------------

.. code:: python

   from opentelemetry import trace  # no dependency on xxp_otel

   tracer = trace.get_tracer(__name__)


   def action_confirm(self):
       # works even if xxp_otel is not installed
       with tracer.start_as_current_span("sale.order.confirm"):
           return super().action_confirm()

3. Trace a method
-----------------

.. code:: python

   from odoo.addons.xxp_otel.telemetry import observe_method  # depends on xxp_otel


   class ResPartner(models.Model):
       _inherit = "res.partner"

       @observe_method(  # span + log record with the arguments
           event="integration.external_api.response",  # optional
           span_name="external_api.document.get",  # optional
           capture_result=True,  # also log the result (default: False)
       )
       def _get_external_document(self, document_id):
           ...

**Tip:** Put code that uses ``observe_method`` into a separate addon,
for example ``xxp_otel_sale``, so the business module can install
without ``xxp_otel``.
